# VoltProof 升级计划：从电路原理图生成 PCB

日期：2026-10-23  
状态：待实施的产品与技术方案；本轮仅制定计划。  
已确认需求：PCB 布线图，包含元件封装、布局、铜线及制板文件。

## 1. 升级目标与首版定位

把 VoltProof 的工作链扩展为：

**需求 → 原理图与仿真验收 → 实物器件和封装确认 → PCB 布局 → 自动布线 → 连通性与设计规则检查 → 制板文件。**

用户在已经验证的电路上点击“生成 PCB”，补齐实物信息后获得可编辑的 KiCad 电路板、二维布线预览、问题清单和制板包。每块板可以追溯到具体电路版本、元件库版本、制造规则和检查结果。

首版服务教学电路与小型模拟原型，优先跑通 RC 滤波、分压、二极管整流、简单晶体管电路，以及使用已审校真实器件的运放电路。继续保留 VoltProof 的核心价值：每项结论都有对应证据。

**建议先交付 Windows 本地版、双层板、最多约 20 个实物元件的受限 MVP。** 规模上限和性能预算在技术验证后调整。这是项目范围建议，不是已经测得的能力。

| 项目 | 首版范围 | 后续扩展 |
|---|---|---|
| 电路输入 | VoltProof 内部原理图、已采用的网表版本 | KiCad 原理图导入；PNG/JPG/PDF 电路图识别 |
| 板型 | 矩形双层板、普通通孔过孔、简单安装孔/禁布区 | 异形板、四层板、复杂叠层 |
| 元件 | 已审校的 R/C/L、二极管、连接器及少量具体型号半导体 | 扩充 IC、模块和供应商物料库 |
| 封装 | 常用通孔、0805，以及审校过的 DIP/SOIC 等 | 细间距、QFN/BGA 等复杂封装 |
| 布局 | 按信号流和局部规则生成；支持移动、旋转、锁定 | 更复杂的多目标优化与布局模板 |
| 布线 | 普通信号/电源网络，顶底层走线；未完成网络明确显示 | 差分、等长、阻抗约束、高密度布线 |
| 用户调整 | 网页调整元件位置；复杂走线修改转到 KiCad | 浏览器内完整交互布线编辑器 |
| 输出 | KiCad 工程、PCB、Gerber、钻孔、BOM、预览与检查报告 | 自动贴装文件、STEP、更多 EDA 格式 |

首版暂不覆盖高速数字、射频、开关电源关键回路和高压隔离设计；这些需要额外的专用约束与验证。制板包导出不包含代下单或自动发送给板厂。

对图片输入采用独立的第二期入口：**识别图像 → 展示元件/节点/连接疑点 → 用户修正为结构化原理图 → 仿真与 PCB 流程**。图片识别通过率、网络识别正确率与 PCB 布线成功率分别评估。

## 2. 与当前代码的衔接

现有代码检查发现，VoltProof 已经具备可复用的项目与验证框架，但目前生成的是逻辑原理图，尚未包含物理 PCB 数据。

| 当前模块 | 可复用能力 | 本次新增内容 |
|---|---|---|
| `app/canvas_layout.py` | 网表解析、信号流排序、原理图几何布局、拓扑终检 | 抽出稳定的元件/引脚/网络数据；PCB 使用独立布局和检查模块 |
| `app/project.py` | 不可变候选、应用、撤销、修订号冲突保护 | PCB 分支版本、源电路绑定、过期状态 |
| `app/pipeline.py`、`app/draw_api.py` | ngspice 验证、指标验收、运行记录 | 实物器件替换后的重新验证；PCB 任务调度 |
| `app/workspace.py` | 工作区路径守卫、项目归档 | PCB 工程与运行产物目录 |
| `app/report.py` | 项目报告与证据聚合 | 引脚映射、制造规则、连通性、DRC 和制板包清单 |
| `app/static/board.js`、`proof.js` | 画布、候选应用、统一结果展示 | 独立 PCB 页签、二维层视图、问题定位 |

当前画布中的 `x/y` 是逻辑格点，器件引脚偏移也是符号绘制数据，不能直接当作毫米坐标和封装焊盘。原理图迷宫布线可以提供算法经验，但不能直接承担铜线宽度、净距、过孔和铺铜的正确性检查。

## 3. 用户流程

1. **选择源电路。** 使用已保存、已验证的电路版本；有未验证修改时先提示验证或选择已有版本。
2. **检查能否实体化。** 列出缺型号、缺电源引脚、未确定仿真源用途、无法展开的子电路等问题。
3. **确认实物器件与封装。** 展示位号、数值、实物引脚、焊盘编号、极性和封装预览；审校库中唯一明确的映射可以预填，歧义项必须补齐。
4. **设置板子。** 选择尺寸、板厚、层数、制造规则模板、连接器位置和安装孔。规则模板包含线宽、净距、孔径、板边距离及必要的网络类别设置。
5. **生成布局候选。** 显示封装与待连接飞线；可以移动、旋转、锁定元件，再重新布局。
6. **运行自动布线。** 显示阶段、耗时、未连接数、过孔数、任务预算与取消入口。保留失败或部分布线的候选，不覆盖当前采用板。
7. **检查与修正。** 展示源电路一致性、引脚映射、连接完整性和 DRC；点选问题定位到相应元件、焊盘或走线。
8. **采用与导出。** 采用通过检查的候选版本；导出可编辑工程或制板包。复杂问题可在 KiCad 修改后回导，再走同一套检查。

页面分开展示“仿真指标达标”“物理连接一致”“PCB 规则检查通过”“实物测试未进行”。DRC 通过不等于已验证寄生参数、热性能、EMC 或实物功能。

## 4. 最先解决：仿真器件到实物焊盘的映射

SPICE 网表主要描述电气行为。PCB 还需要器件的实际引脚、尺寸、封装、供电和外部接口。这是本升级的首要前置条件。

### 4.1 统一电路数据

新增版本化 `CircuitIR`，至少包含：

- 稳定的元件 ID、位号、型号、参数、逻辑引脚和网络 ID。
- 仿真模型及其引脚顺序；实物料号/器件定义及其引脚功能。
- `logical_pin → physical_pin → footprint_pad` 映射。
- 元件角色：板上器件、外部接口、仅仿真使用的激励/探针。
- 明确的无连接引脚、隐藏电源引脚、多单元器件、重复焊盘编号等语义。

现有顶层网表解析不能静默丢掉子电路内部关系。首版对不支持的结构显式阻断，后续增加经过验证的展开与映射规则。

### 4.2 审校过的器件库

每个器件定义保存数据来源、封装文件、引脚表、极性、必要的额定参数、仿真映射和库版本。半导体按具体型号和具体封装审校，不能用“NPN”或“运放”类别推断实际脚位。

关键处理规则：

- 三脚理想运放不能直接变成某个真实 IC。补充供电、真实引脚和必要外围器件后，形成新的电路候选并重新验证。
- 仿真信号源需要明确映射为输入端子、板上信号发生电路或其他实际供电/输入方案。
- 测量探针、零伏检测源、行为源等不能被直接当作实物封装，也不能未经验证就从网络中删除。
- 增加去耦、电源引脚或修改器件型号属于电路修改，不能只在 PCB 层偷偷补上。
- 元件数值相同但实物封装、极性或引脚不同，必须重新检查映射与 PCB。

首版先建立约 20–30 个审校条目，而不是直接导入整个网上元件库。封装尺寸、焊盘和引脚核对由有 PCB 经验的人员参与。

## 5. 推荐技术路线与第一周验证

采用 **VoltProof 管理流程与证据 + KiCad 管理 PCB 数据和设计规则 + Freerouting 负责自动布线**。

KiCad 官方 CLI 支持 PCB DRC、Gerber、钻孔、SVG 等操作，可以承担批量检查和导出。接口细节以锁定版本的帮助和实测为准。[KiCad 10 CLI 文档](https://docs.kicad.org/10.0/en/cli/cli.html)

Freerouting 接受 DSN 设计文件并返回 SES 布线结果；它处理布线，元件布局仍由前置步骤负责。[Freerouting 官方说明](https://github.com/freerouting/freerouting/blob/master/README.md)

### 5.1 版本与接口限制

以 KiCad 10.x 为首个验证基线，开工时锁定具体补丁版本、Python 绑定、Freerouting 和 Java 运行时版本。KiCad 10 的 IPC 连接运行中的 GUI；其 IPC 不提供绘图/导出，相关操作由 CLI 承担。官方文档介绍了 KiCad 11 的新增能力，但本计划不将它当作 10.x 已有能力。[KiCad IPC 官方文档](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/for-addon-developers/)

推荐首版采用本地桌面桥接模式：VoltProof 连接受控的 KiCad PCB 会话，所有操作绑定本任务板文件与实例。纯后台模式另做兼容性验证。

DSN 导出与 SES 回导必须单独做技术验证：**不能假定 `kicad-cli` 已提供这两个命令，也不能假定 IPC 已覆盖全部路由交换操作。** 优先核验官方 IPC 与现有 Freerouting 插件的组合；若需要旧 Python 接口，只允许放在锁定版本的桥接适配器内，并记录迁移代价。Freerouting 的官方集成说明提供 KiCad 插件入口，但完整自动化程度仍需要实测。[官方集成说明](https://github.com/freerouting/freerouting/blob/master/docs/integrations.md)

### 5.2 第一周必须跑通的技术闭环

用一个 RC 电路完成：

`已确认网络和封装 → 未布线 .kicad_pcb → DSN → Freerouting → SES 回导 → 铺铜更新 → 连通性/DRC → Gerber 与钻孔导出`

验证结果必须回答：

- 是否可以自动创建、保存、重开板文件并保留焊盘网络？
- DSN/SES 交换是否保留层、线宽、禁布区、过孔和已有锁定对象？
- 超时或取消后是否可以可靠终止任务并保留原板？
- 在中文路径、带空格路径和干净 Windows 环境中是否可运行？
- 所选集成是否需要用户保持 KiCad 编辑器打开？
- 工具缺失或版本不匹配时，是否给出明确诊断？

若自动交换链路未通过，先交付“生成可编辑 PCB + KiCad 辅助布线”的里程碑，并重新估算自动化阶段；不能把需要手动交换文件的流程标为“一键自动布线”。

### 5.3 能力划分

| 层 | 推荐职责 |
|---|---|
| LLM | 理解要求、建议器件候选、解释问题；建议经结构化校验后才执行 |
| CircuitIR 与器件库 | 网络和引脚语义、实物映射、源版本绑定 |
| 布局模块 | 分组、位置和方向、连接器靠边、去耦邻近、禁布区及锁定规则 |
| KiCad 适配器 | 创建/读取 PCB、封装与网络操作、路由结果交换、保存 |
| Freerouting 适配器 | 运行布线任务、预算和取消、日志与结果接收 |
| 检查模块 | 映射校验、归一化网络对照、实际铜连接与 DRC 结果汇总 |
| 网页 PCB 视图 | 板层预览、网络高亮、元件移动/旋转/锁定、问题定位 |

首次布局采用连接关系分组、信号流次序和少量工程规则，优化总连线长度、拥挤、过孔及关键器件距离。先满足硬约束，再优化这些指标。布不通时保留未连接网络，并建议移动元件或增大板框；不自动放宽制造规则。

## 6. 数据、版本和任务设计

### 6.1 数据边界

- 逻辑电路以 CircuitIR 和其源电路版本为依据。
- PCB 的已保存几何以 `.kicad_pcb` 为依据；网页预览 JSON 从该文件提取，不同时维护两份独立可写的走线真值。
- 初始板可由受审校模板和适配器生成，避免 LLM 直接输出任意 PCB 文件。KiCad 的板文件包含封装、网络、走线、过孔和区域等结构，需按所选版本处理。[官方 PCB 文件格式](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/)
- PCB 版本至少记录 `source_version_id`、电气内容哈希、器件映射哈希、规则哈希、工具版本、任务输入和最终板文件哈希。
- 位置/走线调整形成 PCB 修订，不改变逻辑电路；更换引脚或连接形成新的源电路候选。
- 源电路改变后，对当前 PCB 显示“源电路已更新”。若电气内容哈希一致，可重新核对后绑定；不可仅凭版本号变化或名称变化判定正确性。
- 过期板仍可作为明确标记的历史版本查看和导出；不能冒充当前电路的有效制板结果。

建议归档结构：

```text
<workspace>/
  .cp/pcb_versions/<pcb_version_id>.json
  pcb/<job_id>/
    input/       circuit.json、parts.json、constraints.json
    placement/   未布线板、布局候选
    routing/     DSN、SES、布线日志
    final/       board.kicad_pcb、项目规则、使用到的本地封装库
    checks/      映射、网络一致性、DRC 报告
    fabrication/ Gerber、钻孔、BOM、制造说明、manifest.json
    preview/     分层预览与网页显示数据
```

工作区约束沿用 `Workspace.resolve()`；外部工具通过固定参数的子进程适配器调用。任务有超时、取消、阶段日志和独立目录，不覆盖历史产物。调用实际工具前探测版本及能力，避免假装完成缺失步骤。

### 6.2 状态与任务接口

主状态建议：

`needs_mapping → ready_for_placement → placed → routing → routed → checking → checked`

另外记录 `failed`、`cancelled`、`partial`、`stale`，并独立保存仿真、映射、连通性、DRC、实物测试五类结果。`routed` 仅代表布线任务有产物。

建议新增接口组：

| 接口 | 作用 |
|---|---|
| `GET /api/pcb/capabilities` | 返回工具版本、可用能力与缺失依赖 |
| `POST /api/pcb/preflight` | 绑定源版本，返回映射与设计输入缺项 |
| `POST /api/pcb/jobs` | 提交布局/布线/检查任务，返回任务 ID |
| `GET /api/pcb/jobs/{id}/events` | SSE 进度与结果 |
| `POST /api/pcb/jobs/{id}/cancel` | 取消指定任务 |
| `GET /api/pcb/versions/{id}` | 板版本、预览和证据 |
| `PUT /api/pcb/versions/{id}/placement` | 带修订号提交位置调整，产生新候选 |
| `POST /api/pcb/apply` | 采用指定候选，检查 PCB 与源电路修订号 |
| `POST /api/pcb/export` | 对指定版本执行检查并产生冻结的导出包 |

所有会修改状态的请求携带预期修订号；迟到任务只能留下候选，不得覆盖用户随后修改的板。

## 7. 检查与导出标准

制板包必须从同一个冻结版本生成，检查后若板文件、封装、制造规则或填充铜区发生变化，原检查结论即失效。

| 检查层 | 检查内容 | 通过依据 |
|---|---|---|
| 电路与器件 | 元件、参数、供电、测试源与外部端口转换完整 | 明确映射规则；需要修改时已有新电路验收记录 |
| 引脚到焊盘 | 无漏映射、无歧义、极性及多单元正确 | 审校库定义与实物引脚核对 |
| 网络一致性 | 源电路的预期连接与 PCB 焊盘分组一致 | 按稳定引脚 ID 比较连接分区，允许已声明的外部接口转换 |
| 实际连接 | 铜线/焊盘/过孔/填充区无短接和未完成连接 | 从实际 PCB 连接分析和 DRC 取得结果，不仅检查 net 名称 |
| 物理规则 | 线宽、间距、孔径、板边距离、重叠、板框等 | 所选制造规则下的 DRC 与专项检查 |
| 产物一致性 | 层、板框、钻孔、单位、原点、BOM 对应同一板版本 | 文件清单、哈希、导出后重新读取与预览核对 |

首版要求已导出的“检查通过制板包”零未连接、零短路、零阻断性规则错误，所有实物引脚有明确归属或明确无连接声明。警告逐项保留，处理状态可追溯；不得通过改变严重级别或隐藏错误让结果变绿。

KiCad CLI 可输出 JSON 格式 DRC 报告，并支持补填铜区；实现时解析报告内容、保留排除项，不仅依赖进程退出码。有有效 KiCad 原理图时可以增加原理图一致性检查；只有 SPICE/内部原理图时由 CircuitIR 对照负责。[KiCad DRC 文档](https://docs.kicad.org/10.0/en/cli/cli.html#pcb_drc)

输出包建议包括：

- 可编辑 `.kicad_pcb`、项目规则和使用到的封装库；文件可在干净环境重新打开。
- 顶底铜、阻焊、丝印、板框等适用层的 Gerber 与钻孔文件。
- BOM：位号、数值、封装、数量、已确认型号；未提供采购料号的项目清楚标注。
- 二维预览、DRC/连通性报告、源电路版本及仿真证据索引。
- `manifest.json`：源版本、板版本、规则、工具与库版本、全部文件哈希。

检查不通过仍允许下载明确标为“未验证/待修正”的工程草稿。正式制板包入口按上述条件开放；用户在 KiCad 修改回导后也必须重新检查。

## 8. 实施排期与交付物

估算前提：2 名开发者持续投入，其中 1 人主导后端/EDA 集成、1 人主导前端/测试；另有熟悉 PCB 的人员每周参与器件库与板级审查。建议先预算 **8 个开发周**，第一周验证后重新估算。单人实现可按约 12–16 周预算。均为规划估算，不包含外部打样和采购等待时间。

| 阶段 | 时间 | 重点任务 | 交付与退出条件 |
|---|---|---|---|
| A：技术验证 | 第 1 周 | 锁工具版本；RC 例子完成 PCB→DSN→SES→检查→导出；测试中文路径和取消 | 可复现脚本、真实输出板、接口能力矩阵；据此决定自动化路线 |
| B：实体化与 PCB 骨架 | 第 2–3 周 | CircuitIR、审校器件库、虚拟器件/端口转换、板框/规则、版本绑定 | 从源电路得到可重开的未布线 KiCad 板；映射和网络测试通过 |
| C：布局与预览 | 第 4 周 | 初始布局、连接器与去耦规则、网页位置编辑、网络高亮、锁定 | 用户能看懂、调整并保存布局；约束冲突可定位 |
| D：自动布线与验证 | 第 5–6 周 | 工具适配、任务进度/取消、SES 回导、铜区刷新、连接和 DRC 检查 | 支持范围内生成布线候选；失败保留证据；检查结论可靠 |
| E：导出与发布验证 | 第 7–8 周 | 制板包、工程回导、回归、安装探测、案例文档、人工板级复核 | 候选版本可采用/撤销；导出包完整；干净 Windows 环境通过 |

两个可独立演示的里程碑：

- **M1，第 4 周：** 电路图 → 实物映射 → 可编辑 PCB 布局与飞线，能够交接给 KiCad 继续处理。
- **M2，第 8 周：** 自动布线 → 真实规则检查 → 可追溯制板包。

另安排 2–3 块代表性电路的打样与测试：RC、二极管/晶体管电路、具有真实供电引脚的运放电路。先评审下单文件，再分别记录装配、通断、电源和功能测量结果；只有完成测量的案例才标“实物已验证”。板厂与物流时间单独管理。

## 10. 验收与评估

先建立固定、可复现的测试集：建议 30 个受支持的小板案例，加至少 15 个异常/边界案例。与训练提示、布局调参使用的案例分开标记，记录所有失败，不只展示成功案例。

| 维度 | 建议首版验收目标 |
|---|---|
| 必需连接和脚位 | 每个被系统标为检查通过的板，都与预期网络分区一致；无漏脚、错极性、未声明的网络变更 |
| DRC | 检查通过板零阻断性错误、零未连接、零短路；完整保存警告与排除项 |
| 自动完成率 | 固定受支持案例集内，目标至少 80% 在规定预算内自动完成并通过检查；这是待测目标 |
| 失败可诊断性 | 其余案例明确给出未连接、约束冲突、工具失败或超时；不误报完成 |
| 性能 | 阶段 A 固定测试机器；以 20 元件以内案例的 3 分钟总任务预算作为初始目标，记录中位数/P95 和超时率 |
| 可复现性 | 输入、规则、库和工具版本相同，可复核板文件与检查结论；优化算法若非完全确定，记录可用种子与运行配置，不承诺逐字节相同走线 |
| 版本保护 | 源电路变化会标过期；迟到结果、取消、撤销、重新载入都不会错绑当前板 |
| 导出完整性 | 工程在干净环境可打开；制板文件的层、钻孔、板框、原点及哈希一致 |
| 原功能回归 | 现有五套测试保持通过；没有 PCB 工具时仿真、画图、报告正常使用 |

必须覆盖的异常：晶体管不同封装脚序、二极管极性、缺电源脚、理想运放、仅仿真源、子电路未支持、重复位号、未知封装、重复焊盘号、板框过小、禁布区冲突、锁定器件冲突、异网铜短接、铺铜后产生的连接变化、取消与源版本更新。

产品层另记录“从验证电路到可交付板的用时”“平均需要人工修正的映射/布局次数”“从 M1 到 M2 的完成比例”，用试用数据决定优先扩展元件库还是提高布局质量。

## 11. 首个演示案例

建议使用现有 1kHz RC 低通作为贯穿案例：R1=1.59kΩ，C1=100nF。

1. 从当前已经验收的电路版本开始。
2. 将 AC 激励声明为外接信号输入，确认输入/地连接器 J1；为输出/地添加 J2。生成明确的物理接口转换记录。
3. 为 R1、C1 选择审校过的封装，并确认适用额定参数。
4. 生成简单矩形双层板：J1 靠左，J2 靠右，R/C 在中间，支持手动调整与锁定。
5. 完成布线与检查，在原理图和 PCB 上联动高亮 `in`、`out`、`GND`。
6. 导出板文件、BOM、Gerber、钻孔、检查报告和源仿真证据。
7. 修改 R1 并重新验证，演示旧 PCB 过期、新候选生成及采用/撤销。

这个案例优先验证跨模块闭环；随后再用真实半导体器件检验脚位、电源和封装映射。

## 12. 开工顺序

先完成阶段 A 的接口验证和 RC 全链路样例，形成可运行、可检查的证据，再冻结首版接口与排期。其后优先落实 CircuitIR、审校器件映射和 PCB 版本模型，最后接入页面与更多布局优化。

本计划的正式交付目标是：**在明确支持范围内，把经过仿真验收的电路转换为网络一致、通过规则检查、能继续编辑和导出制板文件的 PCB。**
